  • Two memory stores, unlinked: coding-session memory (public schema: observations/sessions) and graph memory (graph schema) share a DB but no code path joins them.
  • Serving is REST-only (internal/graph/handlers/router.go:18-58) on port :34567 (internal/config/config.go:343, internal/worker/server.go:296); no MCP exists; mem-search skill curls the API.
  • Proactive push already half-exists: detect_hot_topics + notify_watch_channels self-rescheduling jobs DM via slackDM (slack_notify.go).

  • Constraints: ACL built-but-unexercised with a critical /node+/neighbors bypass (docs/reviews/graph-memory-review.md); single binary on one VPS; effectively single-user (EnzoBot DMs you).

Skipped: partner scoreboard (mood pills = weekly LLM judgments that drift), action queue as a format. Kept elements: trend arrows ▲●━▼, evidence links to root threads, similarity callbacks to past clusters, silence when nothing changed.
  • "User" means partners first, travelers later — a future support/CS-feedback fetcher is on the horizon, not in v1.
  • Agency: report-only v1. No Jira filing, no interactive buttons. You act on it.
  • Done in 3 months = "I still open it every Monday and it changes what I do that week." Bar is personal utility, not team adoption — calibrates how much to invest in clustering quality.
  • Audience now, team later — write copy so a forwarded digest stands alone (no "you"-only context).

Kick off the build — copyable prompt

Implement the user-research synthesis agent in agent-mem, from the quadrant-walk map.

Feature: weekly in-worker job `synthesize_user_feedback` + supporting job `sync_synthesis_channels`.

Terminology: the "synthesis set" = the "partners" continent group ∪ the synthesis_internal_channels settings list. (Deliberately NOT called "watched channels" — that term already means the partner-only notifier set, notify_watch_channels.go:15-18.)

Core behavior:
- sync_synthesis_channels: self-rescheduling every 6h; for EVERY channel in the synthesis set, pages conversations.history forward from a persisted per-channel WATERMARK (last-seen message ts). Slack's next_cursor is a short-lived pagination token — reuse backfill_slack_channel's paging only WITHIN a single sync pass; never persist next_cursor across runs. The durable checkpoint is the watermark. The synthesis_internal_channels settings key is the single source of truth for the internal half — the corpus query reads the same key, so sync and synthesis can never diverge.
- synthesize_user_feedback: weekly (working default: Mon morning SGT — confirm exact hour); corpus = last 7 days of raw graph.nodes slack bodies in the "partners" continent group + payments internal channels, LEFT JOIN graph.people p ON p.id = n.author_person_id with COALESCE(p.is_bot,false)=false (inner join would drop messages whose author never resolved), excluding type='agent_report'; cluster into themes (embeddings + LLM, claude-sonnet-5 if configured else Gemini); compute trends by matching theme centroids (>=0.75) against ONLY the immediately-previous agent_report node; DM me a theme-digest (trend arrows, thread counts, evidence permalinks) ending with one 🎯 goal-candidate line; if no changes, write the node but send no DM.
- Write-back: direct insert node id agent_report:<iso-week>, scope='public', author_person_id = new is_bot EnzoBot person, REFERENCES edges to evidence threads, then enqueue index_artifact{force:true}. Never route it through fetch_body.

Hard requirements from the landmine sweep (all must hold):
- Job entry: Heartbeat:true, Lease>=900s (copy refresh_topic_scope, NOT detect_hot_topics).
- Never return a bare error from the handler after the reschedule defer is set (retry+defer doubles the chain); swallow per-item errors.
- ISO-week claim row (new table) claimed BEFORE the DM, rolled back if DM fails.
- Boot-time EXISTS(queued/running) guard in server.go for both new jobs.
- Chunk DMs under Slack limits before slackDM.
- Exclude type='agent_report' from cluster_summary's cluster collection (cluster_summary.go BFS members / linked-resources block) so machine narrative never feeds human cluster summaries (L11).
- Register agent_report in ids.go (const + ParseType) and dashboard maps (ClusterGraph.tsx TYPE_COLOR/LABELLED/LEGEND, Graph.tsx TYPE_COLORS/NODE_TYPES), friendlySource in cluster_summary.go.
- Before coding: audit the partners continent match list (only ext-wego- today; partner-saudi-rail is missing) and add overrides.
